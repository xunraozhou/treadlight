## 一、项目概述

### 1.1 作品简介

《踏光：两拍回响》是一款将音乐节拍、平台跳跃与道路修复结合的 2D 游戏。玩家穿过沉寂的光之遗迹，在断路旁踩拍起跳，唤醒只能存在四拍的青色光桥；随后在桥面踩准节拍落地，将它固定为金色通路。房间内的全部共鸣点被修复后，出口开启。

作品用“起跳造路，落拍留光”贯穿操作与场景变化。节拍既决定玩家行动的时机，也决定道路能否出现、能否被保留。

### 1.2 产品定位

1. **类型：** 单人、横向移动、节奏平台跳跃。
2. **核心体验：** 听见节奏，预判起落，修复断路，看到行动留下的改变。
3. **目标玩家：** 愿意尝试轻量节奏挑战与平台跳跃的玩家；无需掌握复杂连招。
4. **运行平台：** 当前提供 Windows x64 可执行版本。
5. **引擎与语言：** Godot 4.4.1 Standard、GDScript。
6. **当前规模：** 三个短房间，配套标题页、规则教学、暂停、重试、计分与结算。
7. **操作特点：** 左右移动与地面单次跳跃，落地自动判定；无须额外按键确认落拍。

### 1.3 玩家体验目标

1. 初见时能通过虚线桥、节拍灯与教学理解“这里需要造路”。
2. 首次成功起跳后，立即看到青桥出现，建立动作与道路之间的联系。
3. 第一次落拍成功时，通过金色桥面、修复波纹和共鸣进度感到成果被保留。
4. 遇到激光后，学会在安全位置等待，选择合适的节拍行动。
5. 通过三间房间后，能够说明“起跳创造临时通路，落地使通路稳定”这一完整规则。

## 二、创作立意与“律动”的表达

### 2.1 核心立意

一次跳跃会结束，但它可以留下道路。作品把短暂的动作转化为可见的空间改变，让玩家通过反复观察与尝试，逐步修复原本无法通过的环境。

叙事主要由关卡状态承担：暗色断隙变为青桥，青桥变为金桥，共鸣点亮起，出口开启。当前版本以环境、色彩和少量提示表达主题，不依赖长篇对话或过场动画。

### 2.2 律动与系统的对应

| 层面 | 具体设计 | 玩家能够感受到的结果 |
| --- | --- | --- |
| 音乐 | 120 BPM 循环音轨 | 获得稳定的时间参照 |
| 动作 | 普通起跳随时可用；起跳和实际落地接受节拍判定 | 主动选择时机，并观察动作结果 |
| 道路 | 踩拍起跳激活四拍青桥；踩拍落桥将其固定 | 节奏直接改变可行走区域 |
| 危险 | 激光预警、伤害和间歇按拍运行 | 等待与行动具有可预判的周期 |
| 画面 | 四拍灯、收缩光环、桥面颜色和修复波纹 | 同时通过声音与视觉理解节奏 |
| 进程 | 修复全部共鸣点才能开启出口 | 律动操作成为推进关卡的必要条件 |

### 2.3 核心设计特点

1. **把起跳与落地组成完整的节奏动作。** 起跳决定是否造路，落地决定是否留住道路，玩家需要同时考虑时间和空间。
2. **把节奏成绩转化为场景进展。** 成功后不仅增加分数，还会保留金桥并改变出口条件。
3. **保持跳跃轨迹一致。** 普通跳跃和踩拍跳跃使用同一移动参数，节拍主要改变机关状态，便于预判落点。
4. **允许安全等待与补救。** 玩家可以留在平台上等待下一拍；错过落拍后，在桥未消失时寻找退路，也可从任一岸重新激活。
5. **通过规则组合递进。** 第一间学习造桥与留光，第二间加入激光时机，第三间连续完成两段修复。

这些是本作品的玩法特点，不作未经验证的“首创”或同类作品唯一性宣称。

## 三、世界与角色设计

### 3.1 场景背景

旅程发生在失去光亮与连接的几何遗迹。完整的地面被断隙分开，残存的节拍仍在空间中回响。玩家沿着回响前进，用起落恢复断开的通路。

### 3.2 玩家角色

1. 角色以简洁的发光形体呈现，重点突出位置、运动方向与落点。
2. 角色周围的收缩光环提示节拍接近，移动轨迹帮助观察跳跃过程。
3. 当前版本没有职业、装备、技能树或角色养成；能力集中于移动、跳跃和节拍交互。

### 3.3 环境叙事顺序

1. **唤醒余音：** 从第一段断路理解“行动可以唤醒光”。
2. **让光留下：** 在危险与等待中稳定完成修复，理解“留下”需要完整的起落。
3. **接续回响：** 连续修复两段桥，让零散的回应成为通往终点的道路。

## 四、核心玩法与规则

### 4.1 操作

| 操作 | 按键 | 说明 |
| --- | --- | --- |
| 左右移动 | A / D 或 ← / → | 控制地面与空中水平移动 |
| 跳跃 | 空格、W 或 ↑ | 仅从地面起跳；当前无二段跳 |
| 开始、重试或继续 | Enter | 具体作用随所在页面变化 |
| 重开当前房间 | R | 重新开始本房间流程 |
| 暂停 / 继续 | Esc | 结果页和帮助页可返回标题 |
| 判定校准 | [ / ] | 每次调整 10 ms，设置自动保存 |
| 音乐开关 | M | 开关音乐播放声音 |

### 4.2 单个房间的完整循环

1. 阅读提示，经过四拍准备。
2. 观察断路、虚线桥和附近安全平台。
3. 接近光桥，在合适的节拍从地面起跳。
4. 若判定有效，青桥出现，开始四拍倒计时。
5. 保持合适的水平位置，实际落在目标桥面上。
6. 若落地踩拍成功，桥变为金色，共鸣进度增加。
7. 若未修复成功，寻找安全落脚点并重新尝试。
8. 避开有预警的激光，修复本房间全部光桥。
9. 抵达开启的出口，进入下一间或最终结算。

### 4.3 普通跳跃

1. 不要求踩拍，保证基本移动与躲避操作可用。
2. 与踩拍起跳保持相同速度、重力和轨迹。
3. 按键本身不直接授予判定；只在角色实际完成起跳后检查一次。
4. 空中连续按跳跃不会产生新的地面起跳，也不能反复点亮光桥。

### 4.4 起跳造路

1. 角色需位于目标桥附近，并满足起跳的空间条件。
2. 起跳时间与最近节拍进行比较，得到准确、良好或偏拍结果。
3. 准确或良好会激活附近尚未固定的目标桥。
4. 偏拍仍可正常跳跃，但不激活桥。
5. 机关不会因为远处一次踩拍而全部打开，交互以角色附近的目标桥为准。
6. 同一拍不重复接受有效动作判定，避免重复计分。

### 4.5 临时光桥

1. 激活后成为可站立的青色桥面，持续四拍。
2. 最后一拍出现闪烁，提醒玩家即将消失。
3. 到期且尚未固定的桥恢复为不可通行状态。
4. 再次有效激活时，以新的激活时刻计算持续时间。
5. 玩家需要在桥消失前完成固定或回到安全位置。

### 4.6 落拍留光

1. 系统检测角色从空中转为着地的实际时刻。
2. 需要落在本次起跳所关联的、仍然有效的目标桥面上。
3. 落地节拍判定有效后，桥被固定为金色通路。
4. 固定后在本次房间尝试中不再因四拍到期而消失；本房间共鸣进度增加。重开房间会重置桥面与共鸣，不保留为存档进度。
5. 单座桥的修复奖励只发放一次，反复踩踏不能刷取修复分。
6. 落地自动判定，无需在落地时额外按键。

### 4.7 失误与补救

1. 偏拍起跳不会额外改变跳跃高度，玩家仍可完成普通移动。
2. 偏拍落桥时，桥保持原有临时状态，剩余时间不会自动补满。
3. 可以从任一岸重新接近尚未固定的桥，寻找下一次造路和落拍机会。
4. 坠落或碰到危险激光会进入失败流程。
5. 重开当前房间会重置该房间的机关、音乐时间和计分流程；此前的临时状态不能带入新一轮。

### 4.8 激光

1. 当前使用一种横向激光规则，避免过多攻击形态分散学习重点。
2. 每个激光以八拍为周期：一拍预警、一拍危险，其余六拍处于安全间歇。
3. 预警为金色虚线，不造成伤害；危险阶段转为实体亮色光束。
4. 不同机关可设置相位偏移，在同一音乐速度下形成不同的等待时机。
5. 玩家可结合位置、跳跃和周期寻找通过方式；预警必须给出可判断的反应时间。

### 4.9 出口条件

1. 房间内所有光桥均固定后，出口才开启。
2. 仅走到终点附近、仅激活青桥或仅获得分数，不能替代修复要求。
3. 第三间完成后进入最终结算，形成完整的开始—游玩—结束流程。

## 五、数值与反馈

### 5.1 当前关键参数

| 参数 | 当前值 | 设计作用 |
| --- | --- | --- |
| 音乐速度 | 120 BPM | 每拍 0.5 秒，便于建立稳定节奏 |
| 准确判定 | 距最近节拍约 ±80 ms 以内 | 奖励更精确的起落 |
| 良好判定 | 超过准确范围、距最近节拍约 ±150 ms 以内 | 保留初学者可接受的容错 |
| 偏拍 | 超过良好范围 | 不触发有效节拍机关动作 |
| 临时桥持续 | 4 拍，约 2 秒 | 留出落桥或补救时间 |
| 同高起落飞行时间 | 约 1 秒，即 2 拍 | 构成“两拍回响”的基础动作 |
| 水平速度 | 140 像素 / 秒 | 与桥宽、平台距离共同决定路线 |
| 起跳速度 | 向上 530 像素 / 秒 | 决定基础跳跃高度 |
| 重力 | 1060 像素 / 秒² | 决定上升与落下节奏 |
| 桥宽 | 当前每座 200 像素 | 需要利用桥面完成通过 |
| 激光预警 / 危险 | 各 1 拍 | 区分观察时段与危险时段 |
| 开场准备 | 4 拍，约 2 秒 | 给玩家建立节奏的时间 |
| 手动校准 | -250～+250 ms，步长 10 ms | 适配设备与个人感知差异 |

“两拍”是同高起落的近似时间。落点高度、移动位置与碰撞结果会影响实际落地时刻，关卡调试必须结合真实角色物理验证。

### 5.2 计分

1. 起跳有效准确判定：100 分。
2. 起跳有效良好判定：60 分。
3. 首次落拍固定一座桥：额外 120 分，落地不再叠加起跳的 100 / 60 分。
4. 同一座桥不重复发放固定奖励。
5. 出口以共鸣完成度为条件，分数用于反馈操作质量。
6. 准确、良好与偏拍计数统计起跳；落地修复单独计入共鸣进度。
7. 不同拍在安全平台上有效起跳仍可得分；当前去重规则针对同拍重复判定与同桥重复奖励。
8. 失败与重试按房间流程处理；说明与界面必须保持一致。

### 5.3 反馈层级

1. **动作反馈：** 跳跃轨迹、落点与判定提示。
2. **机关反馈：** 青桥出现、末拍闪烁、金桥固定。
3. **进度反馈：** 共鸣点计数、出口状态与结算。
4. **情绪反馈：** 修复波纹和场景色彩恢复，强调“光留下了”。

## 六、关卡设计

### 6.1 总体原则

1. 用安全平台承接等待、观察和再次尝试。
2. 第一间集中教学核心规则，后续房间通过组合增加挑战。
3. 三间保持同一 BPM，不依靠突然变速制造难度。
4. 桥宽、相邻平台高度和可站立位置与实际跳跃轨迹一起调试。
5. 提示应说明失败原因，避免玩家将“桥出现”误认为“修复已经完成”。
6. 不以精确到单帧的操作作为基础通关条件。

### 6.2 第一间：唤醒余音

1. **当前规模：** 场景宽约 2700 像素，一座光桥，无激光。
2. **学习目标：** 识别节拍，理解临时桥与固定桥的区别。
3. **教学顺序：** 移动到断路 → 踩拍起跳 → 观察青桥 → 落拍固定 → 查看出口。
4. **观察重点：** 玩家是否明白落地自动判定，是否知道需要将青桥变为金桥。
5. **验收标准：** 不查阅外部说明，也能通过游戏内提示理解一次完整修复。

### 6.3 第二间：让光留下

1. **当前规模：** 场景宽约 3000 像素，一座光桥、两处激光。
2. **学习目标：** 在音乐节拍与危险周期之间选择行动时机。
3. **挑战结构：** 复用第一间规则，同时观察激光预警和安全间歇。
4. **设计重点：** 预警阶段不伤害，危险阶段清楚可见；玩家有机会停下观察。
5. **验收标准：** 激光阶段与画面一致，失败后能够说明触发失败的原因。

### 6.4 第三间：接续回响

1. **当前规模：** 场景宽约 3400 像素，两座光桥、两处激光。
2. **学习目标：** 连续完成多次起落，在不同位置复用已有规则。
3. **挑战结构：** 两段修复与激光组合，全部共鸣完成后开启终点。
4. **设计重点：** 已固定的桥提供明确进度，避免玩家混淆已完成与未完成目标。
5. **验收标准：** 少修复任意一座桥时出口保持关闭；全部固定后可以正常结算。

### 6.5 时长与难度验证

现有自动角色路线约为第一间 18 秒、第二间 20 秒、第三间 25 秒，不含每间约 2 秒准备时间。这些数据用于确认路线可行，不能代表首次玩家的平均通关时长。首次体验还会包含阅读、观察、等待与重试，应通过实际试玩补充记录。

## 七、美术与声音设计

### 7.1 视觉方向

1. 深色几何遗迹作为底色，用低干扰背景衬托可交互对象。
2. 青色表示临时、可消退的道路，金色表示稳定、已完成的共鸣。
3. 虚线、实体、闪烁和进度文字共同说明状态，尽量降低只靠颜色识别规则的负担。
4. 角色、桥面和危险光束保持足够对比，优先保证落点与危险边界可读。
5. 菜单与游戏内提示保持一致术语：起跳、落拍、光桥、共鸣、出口。

### 7.2 当前画面资源

1. 角色、遗迹、桥面、激光、光环和波纹由工程代码实时绘制。
2. 项目图标为 SVG 矢量图。
3. 标题、玩法、修复、教学和暂停画面已有实际渲染截图。
4. 字体使用操作系统已有字体；中文显示需在目标 Windows 设备复核。

### 7.3 音乐设计

1. 当前配乐为 120 BPM、16 秒循环音轨，由工程附带工具合成。
2. 音乐与机关读取统一时间基准，重复循环时仍需保持判定和画面连贯。
3. 支持音乐开关及手动判定校准。
4. 素材文件与生成工具均在工程中列明，便于复核与后续修改。

### 7.4 后续完善

当前尚未加入独立的修复成功、失败和通关音效。后续可补充短促而不遮盖主拍的声音反馈，并检查整体响度、重复触发与静音行为。这属于音画打磨，不计入当前已完成功能。

## 八、界面与流程

### 8.1 标题与教学

1. 标题页提供开始入口与玩法说明入口。
2. 教学解释青桥四拍、落拍固定和共鸣开门。
3. 使用截图或简短提示帮助玩家将规则与画面对应。

### 8.2 游戏内信息

1. 显示当前房间、得分、共鸣进度和判定反馈。
2. 底部四拍灯显示节拍位置，角色光环提示即将到来的节拍。
3. 重要反馈避免遮挡角色脚下、桥边与激光预警区域。

### 8.3 暂停、失败与结束

1. 暂停时冻结音乐与节拍进程，继续后不因暂停时间造成错拍。
2. 失败后提供清楚的重试入口。
3. 重试重新建立房间初始状态与准备拍。
4. 房间结束后允许继续旅程；最终结束给出完整结算。

### 9.2 时间同步

1. 使用统一的单调时间基准计算音乐开始后的进度。
2. 播放开始时考虑混音等待和输出延迟。
3. 节拍判定、桥持续时间、激光周期和视觉提示共享时钟。
4. 校准值作用于判定时间，避免通过随意改动角色物理掩盖延迟问题。
5. 暂停与重试必须同时处理时钟和音频。

### 9.3 稳定性要求

1. 只对实际起跳和实际着地事件进行判定。
2. 防止同一拍重复触发与同一桥重复奖励。
3. 目标桥的空间范围、存活状态和碰撞支持必须一致。
4. 重试后清除旧目标、旧机关状态与上一轮计分上下文。
5. 可执行包、工程文件和说明对应同一个确定版本。

## 十一、测试与验收

### 11.1 规则测试

1. 准确与良好窗口边界、偏拍与重复判定。
2. 实际地面起跳与空中按键的区别。

4. 中文字体、窗口显示、音频输出和按键说明。
5. 全新解压后的可执行包，以及工程资源首次导入。

v0.2 已有 54 项自动检查和三房间实际角色物理路线验证，历史检查范围见[开发与验证说明](development.md)。这些结果支持规则与路线的可行性，但不能代替陌生玩家体验和独立设备测试。

## 十三、风险与处理

| 风险 | 表现 | 处理与验收 |
| --- | --- | --- |
| 音频延迟 | 听起来踩准却判定偏拍 | 检查统一时钟、延迟补偿和校准，并记录设备 |
| 规则理解不完整 | 青桥出现后直接冲向出口 | 教学与反馈明确落拍固定、共鸣开门 |
| 激光状态不清楚 | 无法分辨预警与伤害 | 检查虚线 / 实体、阶段时长和安全等待位置 |
| 跳跃与布局不匹配 | 成功造桥仍无法稳定落脚 | 用实际角色路线联合调整高度、间距和提示 |
| 重试状态残留 | 得分、桥或音乐沿用旧状态 | 重试后逐项核对初始状态 |
| 文件版本不一致 | 视频、文档与下载包规则不同 | 确定一个提交版本，逐项复核并重打包 |
| 材料工作挤占修复时间 | 截止前仍缺文档或视频 | 明确负责人，优先完成必需项目，冻结新增功能 |
