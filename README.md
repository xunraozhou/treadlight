# 踏光：两拍回响 / Treadlight v0.2

**起跳造路，落拍留光。** 以“律动”为主题的三房间平台游戏：踩拍跳跃生成四拍临时桥，两拍后在桥面踩拍落地，将它修复成永久金桥。修复全部共鸣点，终点才会开启。

![标题](docs/title.png)

## 试玩与工程

- **[下载 v0.2 Windows 试玩包](https://github.com/xunraozhou/treadlight/releases/tag/v0.2.0)**：解压全部文件，双击 `Treadlight.exe`。请把 EXE 与 PCK 保持在同一目录；无需安装 Godot。
- 源码：同页下载 `Treadlight-v0.2-source.zip`，用 **Godot 4.4.1 Standard** 导入根目录 `project.godot`，按 F5 运行。不需要 .NET、插件或额外资产下载。
- **[策划案、手册逐项对照与来源记录](docs/competition-plan.md)**。

v0.2 是独立运行工程，已移除 v0.1 保留的 LIGHT//BOUND 游戏代码、原版入口、编辑器、素材与字体；旧版本和 Git 历史透明保留。v0.1 不应作为本次手册约束下的最终参赛包。

## 两拍回响

| 阶段 | 玩家行动 | 世界变化 |
| --- | --- | --- |
| 起跳造路 | 在虚线光桥附近踩拍起跳 | 青色桥实体化四拍，即两秒 |
| 落拍留光 | 持续向前，在约两拍后落在桥面且仍踩准节拍 | 桥变成金色，永久保留，点亮一个共鸣点 |
| 失误补救 | 偏拍后回到任一岸，再次踩拍起跳落桥 | 可以修复同一段桥；普通跳跃始终可用 |
| 共鸣开门 | 修复房间内所有桥 | 出口开启，抵达后进入下一间 |

准确判定 ±80 ms，良好判定 ±150 ms；两者都能造桥和留光。普通与踩拍跳跃轨迹一致，平地起落约一秒。光桥最后一拍闪烁。激光提前一拍以金色虚线预警，粉色实体危险一拍；可以等待或起跳越过。

![实际地面起跳触发的临时桥](docs/gameplay.png)
![同一次跳跃落桥后生成永久金桥](docs/restored.png)

起跳准确 +100、良好 +60，首次修复一座桥 +120；同拍判定及同桥修复奖励均去重。失败重试清空本房间的桥、时钟和分数，保留前面已通关房间的总光能。

## 操作

| 按键 | 功能 |
| --- | --- |
| A / D、← / → | 左右移动 |
| 空格、W、↑ | 地面起跳；落地自动判定，无需额外按键 |
| R | 当前房间重试 |
| Esc | 暂停/继续；结果或帮助页返回标题 |
| Enter | 开始、失败重试、过关继续 |
| [ / ] | 判定校准每次 -10 / +10 ms，自动保存，范围 ±250 ms |
| M | 音乐开关 |

标题页提供“两拍回响”玩法说明，开场有四拍准备。正校准值接受稍晚的输入；不同音频设备需根据听感调整。

## 三个房间

| 房间 | 教学重点 | 自动路线时间，不含两秒准备 |
| --- | --- | --- |
| 唤醒余音 | 无激光，学习临时造桥与永久留光 | 约 18 秒 |
| 让光留下 | 修复道路与有预警的横向激光 | 约 20 秒 |
| 接续回响 | 两座共鸣桥，全部修复才能开门 | 约 25 秒 |

## 实现与验证

运行代码集中在 `campaign/`：角色移动与真实起落信号、统一音频时钟、光桥、激光、房间流程和 HUD。没有全局旧工程自动加载。相对于研究参考，目标从避激光生存改为“用完整的起落节奏永久修复道路”。

120 BPM 原创合成试作音轨在 `campaign/audio/awakening.wav`，可用 Python 标准库运行 `tools/generate_music.py` 重新生成；没有网络采样。背景、桥、角色、图标均为本项目代码绘制；界面使用系统字体，不随包分发字体。

统一时钟采用 Godot 短歌曲同步方案：单调系统时间减去下一次混音等待和音频输出延迟。判定、光桥、激光与提示读取同一时间；暂停同时冻结音乐与世界时钟。

```powershell
python tools/audit_sources.py
godot --headless --path . --import
godot --headless --path . --script res://tests/run_tests.gd --fixed-fps 60
# Windows 上可使用会检查运行时错误的封装：
./tools/test.ps1 -Godot 'C:/path/to/Godot_v4.4.1-stable_win64_console.exe'
```

**54 项检查**覆盖判定窗口、校准、起跳去重、临时桥过期、永久桥不失效、落拍修复、偏拍不修复、两岸补救、锁门、激光伤害/跳跃、暂停、重试和三关真实物理路线。GitHub Actions 另检查所有运行资源引用均位于独立工程内部。机器人路线只提供方向和跳跃输入，不传送、不关闭伤害；个别边界测试会单独设置初始位置和时间。

文档截图由 `tests/capture.gd` 在 Godot OpenGL 下生成：临时桥和永久桥来自同一次真实起落的受控演示。测试、截图脚本与文档不进入可玩包。首次真人体验、特定耳机的延迟和比赛资格不属于这些自动检查能证明的内容。

## 手册约束与来源

用户提供的手册规定主题为“律动”，且“仅美术素材和音乐音效素材可使用网络素材但必须注明”。因此 v0.2 移除了上游游戏代码依赖，并提供独立源码与素材来源记录。研究参考为 [FireEntity1 / LIGHT//BOUND](https://github.com/FireEntity1/lightbound-demo)，不把其代码作为本版提交内容。

**本项目使用 AI 辅助编程和设计。手册没有说明 AI 辅助是否允许，且要求非团队成员不得参与创作；需要由参赛者向主办方确认，不能保证参赛资格。** 参赛手册要求的正式视频、PPT、讲稿与百度网盘提交尚未完成；本仓库提供的是可玩原型、源码和策划案基础。
